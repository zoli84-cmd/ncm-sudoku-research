# WP2 Confirmatory Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build every runner and the evaluation script for the confirmatory WP2 run of the locked protocol, covering E1, E2 (H2, H3) and E3 (H1) on TEST. Then freeze the code as tag `wp2-code`, run the dry run, and run TEST once.

**Architecture:**
- **Shared module `wp2.py`:** data roles (`test`, `dry`), TEST hash verification, the fail-closed code-freeze guard (parent code paths and the upstream worktree), run records that separate `complete` from `valid`, rerun and resume rules, content manifests, technical-only status lines, and atomic writes.
- **E2:** `e2p2.run_pilot2` is split into resumable stages and gains two opt-in parameters: 50-row outcome decoding (`decode_chunk`) and the §7.2–7.4 diagnostics (`diagnostics`, D78). With both left at their defaults its output does not change; `scripts/wp2_e2.py` drives the stages and sets both.
- **E3:** the existing probe and control functions gain a third data set (train on PROBE-TRAIN, select on PROBE-VAL, score on the role's score set). `wp2e3.py` defines the confirmatory stages, including the §8.2 controls and the training-size curve on the primary whole-layer probe, and `scripts/wp2_e3.py` runs them, saves models, PCAs, predictions and the full grid-by-seed budget, and validates a SHA-256 manifest of every consumed and produced file on resume.
- **Evaluation and dry check:** `wp2eval.py` holds the decision statistics and the mechanical §13 readings. `scripts/wp2_evaluate.py` reads only raw outputs and refuses any run record that is not valid. `scripts/wp2_dry_check.py` compares the dry run with the pre-lock records; its `technical_success` gates every TEST run.

**Tech Stack:** Python 3.12, torch 2.15 (CPU, FP32, eager, deterministic), numpy 2.5.4 and pytest, managed with `uv`. No new dependencies.

**Spec:** `research_plan_v3.7.md` (tag `prereg-v3.7`) §5.2, §6, §7, §8, §10, §11, §12.2 and §13. `DECISIONS.md` D53–D78; D76 is the WP2 process, D77 the accepted spec ambiguities 1–21, D78 plan review round 1 (ambiguities 2, 3, 11, 13 and 16 revised; 22–24 added). Executors read the spec sections their task names.

## Spec ambiguities

For each item: the plan section involved, the reading this plan implements (closest to the text), and why it is flagged.

1. **Whole-layer θ₁ at level 2 (§8.3).** §8.3 says the same θ₁ is reported at levels 2 and 12. With the v3.7 primary probe (whole-layer), this needs a whole-layer level-2 stage: generated probe plus permuted control. D67 ran whole-layer levels 6 and 12 only, so this stage has no pre-lock reference value.
2. **Construction of the §8.2 controls (revised after review round 1, user decision).** Neither §8.2 nor the §12.2 main-table list says which construction the random, label-permutation and teacher rows use. The plan runs them on **both** constructions:
   - the D64 `run_controls` matrix at level 6 with **per-cell** inputs (raw linear and MLP, peer counts, rule, surface, permuted, random, label permutation, teacher L2/L6/L12, marginal), kept so that the dry run reproduces D64;
   - the D67 **whole-layer** rows (generated, permuted, raw projected, raw unprojected, teacher L12), plus new whole-layer level-6 rows for the primary probe: size-matched random features (512-d, the whole-layer feature width), label permutation, and teacher L6 (own teacher PCA on `T06.npy`).

   Relative differences in the main table are computed only within one feature construction (Task 12).
3. **Training-size curve (§8.2, revised after review round 1, user decision).** Two curves at 125, 250, 500, 1,000 and 2,000 PROBE-TRAIN puzzles, each scored on the score set: the whole-layer level-6 curve (primary probe), and the D64 per-cell level-6 curve (secondary; it reproduces D64 in the dry run). The whole-layer PCA stays fitted on all 2,000 PROBE-TRAIN puzzles, because it uses no labels; only the probe's labelled training rows are reduced. Conclusions about the primary probe's data requirements come from the whole-layer curve only.
4. **12-level descriptive curve (D56).** v3.7 does not list it, so it is not run on TEST.
5. **MLP (§8.1).** "Same grid" is read as the D55/D64 per-cell MLP at levels 2, 6 and 12.
6. **Equivariance tolerance (§8.4, §12.2).** The text fixes 0.0116, while the measured value in `experiments/lock/equivariance_l12.json` is 0.011644554557515473. The runner passes the constant `0.0116` exactly, and the TEST seed-noise P95 is reported alongside.
7. **Exploratory equivariance readings (§13) — no mechanical selection (D77).** The locked plan gives no numeric criterion for "accurate" or "equivariant", so the evaluation reports the numbers only (mean deviation, share within the fixed tolerance 0.0116, transformed vs. untransformed Brier per category) and selects no §13 equivariance row; the report states that the reading is descriptive.
8. **"Clearly above the null control" (§13, level-12 row).** Read as: the 95% interval of the whole-layer level-12 θ₁ lies above 0.
9. **Results with no §13 row.** H2 with θ₂ above 0 (the late level is more sensitive) and H3 with θ_comp below 0 have no row. They are reported as "no pre-specified reading", with direction and interval.
10. **"Raw-input baseline reaches the ceiling" (§13).** No numeric criterion is given. The raw and rule Briers are tabulated, and the row is never selected mechanically.
11. **Dry-run E2 size (D77, revised after review round 1).** The dry run uses the first 50 CAL puzzles, exactly pilot 2's first generation chunk of 50, so generation and the damage computations (cumulative states and decoder logits, already chunked by 50 in pilot 2) see the same batches as pilot 2. **Outcome decoding differs:** pilot 2 decoded every branch's whole tensor in one `decode_codes` call (`e2._eval`, 300 rows), while every WP2 run decodes in 50-row batches (`decode_chunk=50`, Task 2), in both roles. Exact equality with the pilot-2 records (and with `level1_full_batch.json`, also decoded at 300 rows) is the pass criterion, so the dry run is also the direct test that decoding is batch-size invariant (300 rows vs. 50). Any difference stops the run before TEST.
12. **E1 in the dry run.** D76(3) names only E2 and E3. E1 runs on the same 50 CAL puzzles and is cross-checked against the pilot-2 `solve_A` values of all 50 ids.
13. **E1 batch size (revised after review round 1).** It is 50 (WP1 used 128), so that E1, E2 (generation chunk 50, decoding chunk 50) and the E3 extraction (batch 50) generate and decode under the same batch composition. E1 decodes per 50-row batch, unlike pilot 2's 300-row outcome decoding (item 11).
14. **McNemar (§11.2).** v3.7 pre-designates no single binary pair, so McNemar is not computed.
15. **Candidate-count MAE (§8.3).** Uses counts thresholded at 0.5, the fixed threshold of every thresholded metric.
16. **Hidden-single metric (§5.1, §8.3, revised after review round 1).** F1 over (puzzle, unit, digit, cell) items; a prediction matches only with the same cell. The truth is `labels.hidden_singles`, which returns (unit, digit 1..9, cell) triples. The prediction, for each digit missing from unit u, is "exactly one empty cell of u has p ≥ 0.5 for that digit", which names the cell. Hidden-only F1 removes, on the truth side, items whose cell is a naked single in `candidate_mask`, and, on the prediction side, items whose cell is a predicted naked single (exactly one digit with p ≥ 0.5). F1 = 2 tp / (n_true + n_pred); None only when both counts are 0, so true items with tp = 0 give 0.0.
17. **Random features for TEST puzzles (§8.2 item 5).** The seed-0 stream is ordered train, then val, then the score puzzles that are not in val. In the dry run the score set is PROBE-VAL, so those puzzles reuse their val rows.
18. **Secondary H1 analyses.** The per-cell θ₁ at levels 2, 6 and 12 and the whole-layer θ₁ at levels 2 and 12 get 95% intervals only, because no TOST is specified. Seed stability (§11.1) is reported as per-seed θ₁ means without intervals.
19. **Correct-baseline breakdown (§7.4).** θ₂ and θ_comp are restricted to puzzles with `solve_A = 1`, with 95% intervals.
20. **"Clean in the code paths" (D76(2), D74).** Means `git status --porcelain -- src scripts pyproject.toml uv.lock` is empty, untracked files included. Any commit after the tag moves HEAD, so dry outputs, docs and `DECISIONS.md` entries stay uncommitted until every TEST run is complete.
21. **Infrastructure reruns (§10).** The TEST role never accepts `--force`. An interrupted run continues only with `--resume` and only while it is incomplete; anything else is a logged deviation. All five runners accept `--resume`: E2 and E3 continue from validated stages; E1, the E3 extraction and equivariance are short and restart cleanly after the same input, code and environment checks.
22. **E2 propagation diagnostics (§7.2, §7.4) — D78.** §7.2 asks for the replacement's vector norm, frequency and conditional probability; §7.4 asks for later-level code changes, full-length cumulative states, intermediate decodings and a level × cell error map. The plan implements:
    - for every E2 record: the cell-level change vectors of C and D against A (from the argmax token at each cell's output position, defined also with format errors), the per-later-level counts of D codes that differ from A, and, per replaced position, the generator's conditional probability of the replacement and of the original value (temperature-1 softmax of the generator logits for that level, given the puzzle prefix and A's earlier levels), the replacement's frozen CAL frequency, and the replacement-vector norm;
    - for the primary configurations only (all level-1 values; level 11, frequency policy, dose 1, seeds 0–2): per level k, the relative distance of the cumulative state of C and of D from A's, and the cell-level difference of the level-k intermediate decodings from A's.

    Full state tensors are not saved. This narrowing is logged as D78 under §7.4's closing sentence ("We report if only the final sensitivity is estimable"), and the report states it (Task 12).
23. **Identity failures (§7.1, §11.2).** In a deterministic, correctly restarted run B = A. Any sham mismatch (B1 ≠ A, or B ≠ A at a level) or level-1 no-op mismatch makes the E2 record `valid: false` with status `identity-failure`: compensation can then leave [−1, 1] and the rare-event bound does not hold. Raw artifacts are kept; the evaluation computes no E2 interval, TOST, AUC or reading and states that a logged deviation is required.
24. **Complete vs. valid (D76(2)).** `complete` means the runner finished. `valid` additionally means the freeze state was frozen at start and at finish, the code state did not change during the run, the code commit equals the tag commit, and (E2) zero identity failures. Only valid records gate TEST runs or enter the evaluation; a run that finished outside the freeze stays invalid even if the worktree is restored later.

## Review Focus

1. **A run finishes outside the freeze and the worktree is restored afterwards** (an edit in `src/`, `scripts/` or `third_party/ncm`, or a commit that moves HEAD, during or between runs). Expected: the record is `valid: false`, no TEST run starts on it, and the evaluation refuses it even though `freeze_state()` is frozen again. Tests: Task 1 `test_freeze_state_upstream_dirty_unfreezes`, `test_freeze_state_missing_tag_not_frozen`, `test_finish_run_invalid_when_code_changed`; Task 12 `test_wp2_evaluate_rejects_restored_worktree_record`.
2. **A long run is interrupted** (reboot or crash during the ≈ 10 h E2 or the ≈ 6.4 h E3), including between publishing A and recording its hash, or after an input file was replaced with identical ids. Expected: `--resume` continues with identical output, no stage is duplicated or lost, and any changed input or artifact is rejected. Tests: Task 3 `test_wp2_e2_resume_after_crash`, `test_wp2_e2_crash_between_A_and_record`; Task 9 `test_wp2_e3_stage_without_artifacts_is_rerun`, `test_wp2_e3_resume_rejects_altered_input_same_ids`.
3. **Results leak before all runs are complete (D76(5)).** Expected: stdout and run records of every runner carry technical fields only. Tests: `test_wp2_<runner>_stdout_is_technical_only` in Tasks 3, 4, 7, 9 and 10; Task 7 `test_wp2_e3_extract_record_has_no_outcome`.
4. **The dry run cannot detect a code-path difference that only TEST exercises** (decoding batch size; score set ≠ PROBE-VAL; random features for new score ids). Expected: decoding is chunked identically in both roles and checked by exact dry equality; the distinct-score path is exercised by a synthetic integration test over every stage. Tests: Task 2 `test_decode_chunk_batches_and_output_unchanged`; Task 9 `test_wp2_e3_distinct_score_set_all_stages`.
5. **An identity check fails (B ≠ A or a no-op mismatch).** Expected: the E2 record is invalid with status `identity-failure`, the dry check fails, and the evaluation computes no E2 interval or reading. Tests: Task 3 `test_wp2_e2_identity_failure_invalidates_record`; Task 12 `test_wp2_evaluate_e2_identity_failure_blocks_inference`.
6. **NaN per-puzzle values or partially eligible puzzles enter a contrast or a TOST.** Expected: they are dropped, counted and reported, never set to zero; an all-NaN input is never "equivalent". Tests: Task 11 `test_contrast_drops_nan_and_counts`, `test_tost_drops_nan_and_empty_is_not_equivalent`.

**Files:**

**Interfaces:**
- Consumes: `g0.code_state`, `g0.environment_record`, `g0.CODE_PATHS`, `model.ROOT`.
- Produces:
  - `subsets.sha256_ids(ids: list[str]) -> str` and `subsets.sha256_array(a: np.ndarray) -> str`.

Every runner prints only through it.

- Produces:
  - `e2._eval_tokens(puzzles, solutions, codes, m, decode_chunk: int | None = None) -> tuple[torch.Tensor, list, list]` (tokens, parsed, metrics); `_eval(..., decode_chunk=None)` returns its last two items. With `decode_chunk=None` it makes the single whole-tensor `decode_codes` call of today; with an int it decodes through `_chunked(..., decode_chunk)`.
  - `intervene.level_logits(m, prefix_tokens: torch.Tensor, given_codes: torch.Tensor, level: int) -> torch.Tensor`: the generator logits [B, n_level, 16] for `level` given the prefix and `given_codes` levels 1..level−1, mirroring `continue_generation` (level 1: the query logits of `_level0_from_queries`). Its argmax equals the greedy codes of that level.
  - `branch_context(..., decode_chunk: int | None = None, diagnostics: bool = False)`: stores `decode_chunk`; with `diagnostics` it also stores A's decoded tokens and `code_probs[level]` (softmax at temperature 1 of `level_logits(prefix, A, level)`, float32 [n, n_level, 16], computed once per level in 1, 2, 6, 11, chunked by `chunk`).

  - Diagnostic arrays per stage (rows in the stage's record order; `diag="basic"` for every stage):
    - `changed_C`, `changed_D`: bool [rows, 81], the argmax token at each cell's output position (`CELL_TOKEN_INDICES`) differs from A's;
    - `later_changes_D`: int16 [rows, 12], per level the number of D codes that differ from A (0 at levels ≤ the intervention level; the row sum equals `downstream_changes_D`);
    - `positions`, `orig`, `new`: int16 [rows, dose] (level 1: position 0, new = v);
    - `p_new`, `p_orig`: float32 [rows, dose], `ctx["code_probs"][level]` at the replaced position for the new and the original value;
    - `freq_new`: float32 [rows, dose], the frozen CAL frequency of the new value;
    - `replacement_norm`: float32 [rows], the L2 norm of the stacked replaced codebook-vector differences in the level's embedding space (equals `codebook_rms · sqrt(dose)`);
    - ineligible rows: positions −1 and NaN probabilities, frequencies and norms;
    - with `diag="full"` (primary stages only) also `state_dist_C`, `state_dist_D`: float32 [rows, 12], ‖z_k^X − z_k^A‖₂ / ‖z_k^A‖₂ on the full-length cumulative state after level k; and `level_changed_C`, `level_changed_D`: bool [rows, 12, 81], the level-k intermediate decoding (`decode_state`) differs from A's level-k decoding at that cell.
  - Level-1 records are shared by both policies, so a level-1 stage carries one set of arrays.
  - `level1_value(ctx: dict, a1: torch.Tensor, w: dict[str, torch.Tensor], puzzle_ids: list[str], v: int) -> list[dict]`: the records of one level-1 value, exactly as the current loop body. `level1_enumeration` becomes a loop over it.
  - `stage_keys(levels: tuple[int, ...]) -> list[str]` in run order:
    - `"base"`;
    - `"level1/v00"` … `"level1/v15"`;
    - per level in `LEVELS_P2`: `f"L{level:02d}/B"`, then `f"L{level:02d}/{policy}/d{dose:02d}/s{seed}"` in `POLICIES` × dose grid × `SEEDS_P2` order.
  - `run_pilot2(m, puzzles, solutions, puzzle_ids, chunk=50, frozen_freqs=None, A: torch.Tensor | None = None, done: dict[str, list] | None = None, on_stage: Callable[[str, list, dict | None], None] | None = None, decode_chunk: int | None = None, diagnostics: bool = False) -> dict`. Stage values:
    - `"base"`: the `baseline_b1` list;
    - `"level1/vXX"`: the `level1_value` list;
    - `"LXX/B"`: `list[int]` of `solve_B`;
    - configuration stages: their record list.
    
    Stages present in `done` are reused without computation (`done` must come from a validated resume; Task 3). `on_stage(key, value, diag)` is called after each newly computed stage; `diag` is the stage's diagnostic arrays, or None when `diagnostics` is False or the stage has none (`base`, `LXX/B`). With `decode_chunk=None` and `diagnostics=False` the output dict is identical to the current one, so every pre-lock caller is unchanged; WP2 runners pass `decode_chunk=50, diagnostics=True`, and the records are then still the same 20 fields (diagnostics go only to `diag`).

    - H1: fl > 0 and tost_eq → `h1_small_positive`; tost_eq and fl ≤ 0 ≤ fh → `h1_no_practical`; fh < 0 → `h1_negative`; fl > 0 and not tost_eq → `h1_readable_not_equiv`; otherwise → `non_significant`. `probe_beats_null` is added whenever fl > 0.
    - H2: fh < 0 → `early_sensitivity`; fl ≤ 0 ≤ fh → `non_significant`; fl > 0 → row None, reason "late level more sensitive".
    - H3: fl > 0 → `d_better_than_c` and `positive_compensation`; contains 0 → `non_significant`; fh < 0 → row None, reason "negative compensation".
    - θ₂′: equivalent → `levels_2_11_equiv`; not equivalent and l95 ≤ 0 ≤ h95 → `non_significant`; not equivalent and the 95% interval excludes 0 → row None, reason "θ₂′ not equivalent; 95% interval excludes 0".
    - Level 12: `theta1_L12_wl` l95 > 0 and θ_T equivalent → `l12_solution_content`; otherwise → row None, reason "level-12 criterion not met" with which part failed.
    - E2 identity failure: when `r["H2"]`, `r["H3"]` or `r["theta2_prime"]` carries `status: "identity-failure"`, no reading is produced for them; one reading with hypothesis `"E2"`, row None and the note "E2 identity failure: a logged deviation is required before any E2 inference" replaces them.
    - Equivariance (exploratory): row None, `note` `EQUIV_READING`, with the numbers in `inputs`. Task 12 writes the same constant as `tables.equivariance.equivariance_reading`.
