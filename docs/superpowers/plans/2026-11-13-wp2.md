# WP2 Confirmatory Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build every runner and the evaluation script for the confirmatory WP2 run of the locked protocol, covering E1, E2 (H2, H3) and E3 (H1) on TEST. Then freeze the code as tag `wp2-code`, run the dry run, and run TEST once.

**Architecture:**
- **Shared module `wp2.py`:** data roles (`test`, `dry`), TEST hash verification, the code-freeze guard, run records with rerun and resume rules, and atomic writes.
- **E2:** `e2p2.run_pilot2` is split into resumable stages. Its output does not change; `scripts/wp2_e2.py` drives the stages.
- **E3:** the existing probe and control functions gain a third data set (train on PROBE-TRAIN, select on PROBE-VAL, score on the role's score set). `wp2e3.py` defines the confirmatory stages, and `scripts/wp2_e3.py` runs them, saves models and PCAs, and records per-puzzle Brier values and predictions.
- **Evaluation and dry check:** `wp2eval.py` holds the decision statistics and the mechanical §13 readings. `scripts/wp2_evaluate.py` reads only raw outputs. `scripts/wp2_dry_check.py` compares the dry run with the pre-lock records.

**Tech Stack:** Python 3.12, torch 2.15 (CPU, FP32, eager, deterministic), numpy 2.5.4 and pytest, managed with `uv`. No new dependencies.

**Spec:** `research_plan_v3.7.md` (tag `prereg-v3.7`) §6, §7, §8, §10, §11, §12.2 and §13. `DECISIONS.md` D53–D76; D76 is the WP2 process. Executors read the spec sections their task names.

## Spec ambiguities

For each item: the plan section involved, the reading this plan implements (closest to the text), and why it is flagged.

1. **Whole-layer θ₁ at level 2 (§8.3).** §8.3 says the same θ₁ is reported at levels 2 and 12. With the v3.7 primary probe (whole-layer), this needs a whole-layer level-2 stage: generated probe plus permuted control. D67 ran whole-layer levels 6 and 12 only, so this stage has no pre-lock reference value.
2. **Construction of the §8.2 controls.** The plan reruns the D64 `run_controls` matrix at level 6 with **per-cell** inputs: raw linear and MLP, peer counts, rule, surface, permuted, random, label permutation, teacher L2/L6/L12, and marginal. The plan also runs the D67 **whole-layer** rows: generated, permuted, raw projected, raw unprojected, and teacher L12. Neither §8.2 nor the §12.2 main-table list says which construction the random, label-permutation and surface rows use. The pre-lock pipeline is kept so that the dry run can be compared with D64/D67.
3. **Training-size curve (§8.2).** The D64 per-cell level-6 curve (125, 250, 500, 1,000, 2,000 PROBE-TRAIN puzzles) is rerun and scored on the score set. There is no whole-layer curve, because the PCA is fitted on the full PROBE-TRAIN.
4. **12-level descriptive curve (D56).** v3.7 does not list it, so it is not run on TEST.
5. **MLP (§8.1).** "Same grid" is read as the D55/D64 per-cell MLP at levels 2, 6 and 12.
6. **Equivariance tolerance (§8.4, §12.2).** The text fixes 0.0116, while the measured value in `experiments/lock/equivariance_l12.json` is 0.011644554557515473. The runner passes the constant `0.0116` exactly, and the TEST seed-noise P95 is reported alongside.
7. **Mechanical exploratory equivariance readings (§13).** "Accurate" means that, in every category, the mean Brier on transformed puzzles is within ±0.01 of the untransformed Brier (the §8.3 practical threshold). "Equivariant at the seed-noise tolerance" means a share within the tolerance of at least 0.95 in every category, because the tolerance is a 95th percentile. The plan text gives neither number.
8. **"Clearly above the null control" (§13, level-12 row).** Read as: the 95% interval of the whole-layer level-12 θ₁ lies above 0.
9. **Results with no §13 row.** H2 with θ₂ above 0 (the late level is more sensitive) and H3 with θ_comp below 0 have no row. They are reported as "no pre-specified reading", with direction and interval.
10. **"Raw-input baseline reaches the ceiling" (§13).** No numeric criterion is given. The raw and rule Briers are tabulated, and the row is never selected mechanically.
11. **Batch composition in the dry-run E2 (D76(3)).** The 30 CAL puzzles form one chunk of 30, while pilot 2 used chunks of 50. §2.2 item 5 guarantees repeatability only for identical shapes. D74 found exact equality across batch compositions on CPU, so exact equality is the pass criterion, and any difference stops the run before TEST.
12. **E1 in the dry run.** D76(3) names only E2 and E3. E1 runs on the same 30 CAL puzzles and is cross-checked against the pilot-2 `solve_A` values.
13. **E1 batch size.** It is 50 (WP1 used 128), so that E1, E2 (chunk 50) and the E3 extraction (batch 50) generate under the same batch composition.
14. **McNemar (§11.2).** v3.7 pre-designates no single binary pair, so McNemar is not computed.
15. **Candidate-count MAE (§8.3).** Uses counts thresholded at 0.5, the fixed threshold of every thresholded metric.
16. **Hidden-single metric (§5.1, §8.3).** F1 over (puzzle, unit, missing digit) triples. The truth is `labels.hidden_singles`. The prediction is "exactly one empty cell of the unit has p ≥ 0.5". Hidden-only triples (where the target cell is not also a naked single) are reported separately.
17. **Random features for TEST puzzles (§8.2 item 5).** The seed-0 stream is ordered train, then val, then the score puzzles that are not in val. In the dry run the score set is PROBE-VAL, so those puzzles reuse their val rows.
18. **Secondary H1 analyses.** The per-cell θ₁ at levels 2, 6 and 12 and the whole-layer θ₁ at levels 2 and 12 get 95% intervals only, because no TOST is specified. Seed stability (§11.1) is reported as per-seed θ₁ means without intervals.
19. **Correct-baseline breakdown (§7.4).** θ₂ and θ_comp are restricted to puzzles with `solve_A = 1`, with 95% intervals.
20. **"Clean in the code paths" (D76(2), D74).** Means `git status --porcelain -- src scripts pyproject.toml uv.lock` is empty, untracked files included. Any commit after the tag moves HEAD, so dry outputs, docs and `DECISIONS.md` entries stay uncommitted until every TEST run is complete.
21. **Infrastructure reruns (§10).** The TEST role never accepts `--force`. An interrupted run continues only with `--resume` and only while it is incomplete; anything else is a logged deviation.

## Review Focus

1. **A long run is interrupted** (reboot or crash during the 8 h E2 or the 5 h E3). Expected: `--resume` continues with identical output, and no stage is duplicated or lost. A stage counts as done only after its artifacts are written. Tests: Task 3 `test_wp2_e2_resume_after_crash`, Task 9 `test_wp2_e3_stage_without_artifacts_is_rerun`.
2. **A file appears in `src/` or `scripts/`, or HEAD moves (for example a commit of dry outputs), between the tag and the TEST runs.** Expected: the TEST role refuses to start, and the finish record shows a changed code state. Tests: Task 1 `test_freeze_state_untracked_file_is_dirty`, `test_finish_run_records_code_change`.
3. **Results leak before all runs are complete (D76(5)).** Expected: runner stdout carries no metric values. Tests: Task 3 `test_wp2_e2_stdout_is_technical_only`, Task 9 `test_wp2_e3_stdout_is_technical_only`.
4. **The dry run's three-set path differs from the two-set path used before the lock**, which would make the dry comparison fail for a code reason. Expected: score = val reproduces the old fits exactly. Test: Task 5 `test_fit_cells_score_equal_val_reproduces_two_set_fit`.
5. **NaN per-puzzle values or partially eligible puzzles enter a contrast.** Expected: they are dropped, counted and reported, never set to zero. Test: Task 11 `test_contrast_drops_nan_and_counts`.
