# E3 Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and run the E3 preparation on PROBE-TRAIN and PROBE-VAL. It covers four things:
- exact canonical-form screening;
- state and label extraction;
- probes and all controls (§8.2), the unit–digit target, depth breakdown and training-size curve;
- an equivariance pilot and the H1 sample size.

The point is that every E3 field of the lock checklist (§12.2) can be filled from measured data.

**Architecture:** New modules:
- `symmetry.py`: the Sudoku symmetry group and the canonical form;
- `e3data.py`: subset generation, state extraction, labels and features;
- `probes.py`: probe training and the Brier endpoint;
- `e3controls.py`: control feature and label constructions;
- `e3equiv.py`: the equivariance pilot.

`power.py` gets the H1 scenario. There are three scripts: extraction, the probe suite, and equivariance plus sample size. Large arrays go to the git-ignored `runs/e3prep/`, one `.npy` file per level and branch. Summaries go to `experiments/e3prep/`.

**Tech Stack:** Python 3.12, torch 2.15 (CPU, FP32, deterministic), numpy, pytest. No new dependencies.

**Spec:** `research_plan_v3.6.md` §4, §5, §8, §11.4, §12.1, §12.2. `DECISIONS.md` D54–D61 (and D16, D36). `literature/kniazev_fijalkow_2026_unit_probe.md` is the binding definition of the unit–digit target.

## Global Constraints

- All files in English. FP32, eager, `torch.use_deterministic_algorithms(True)`, CPU on native Windows (D30).
- Never modify `third_party/ncm`. Load checkpoints only through `ncm_sudoku.model.load_model`.
- **Subsets:** PROBE-TRAIN = `generate_subset("probe_train", 2000)`, PROBE-VAL = `generate_subset("probe_val", 500)`. Never generate SELECT, TEST or E4-TEST.
- **Representation:** the cumulative state Z_{≤ℓ} of the **generated** branch (codes from `generate_codes`). Take it at the cell token positions (`cell_states`, `CELL_TOKEN_INDICES`); embed_dim is 256.
- **Teacher representation:** the same, from `teacher_codes(m, solutions)`.
- **Labels:**
  - initial candidate mask: `candidate_mask(puzzle)`, 9 bits per cell; it is evaluated only on originally empty cells;
  - depth: `inference_waves(puzzle).depth`, with categories 1, 2, 3, ≥4 and stuck.
- **Brier (§8.3):** for each empty cell, the mean over 9 bits of (p − y)². Average that per puzzle over its empty cells, then across puzzles.
- **Primary probe:**
  - input: [cell state (256) ‖ one-hot cell position (81)];
  - a linear layer shared across cells, with 9 sigmoid outputs and BCE loss;
  - only empty cells are used as training examples.
- **Training (D55):**
  - AdamW, minibatch 4096 cell examples, at most 50 epochs;
  - keep the epoch with the best PROBE-VAL Brier;
  - grid: weight decay {0, 1e-4, 1e-3, 1e-2, 1e-1} × learning rate {1e-3, 3e-3};
  - training seeds {0, 1, 2};
  - the selected configuration is the one with the lowest mean PROBE-VAL Brier over seeds.
- **Secondary MLP:** 64 hidden units, ReLU, same grid.
- **Levels:**
  - 2, 6 and 12, linear and MLP;
  - all levels 1–12, linear only (descriptive curve).
- **Controls (§8.2, D57), each trained with the same grid and budget:**
  1. raw puzzle: own cell one-hot (10) ‖ the 20 peers' one-hots in the order of `PEERS[c]` (200) ‖ position one-hot (81); linear and MLP;
  2. peer digit counts: for each digit 1–9, the number of peers holding it (9) ‖ position; linear; the exact `candidate_mask` rule is reported as Brier 0 (ceiling);
  3. surface: clue count (1, scaled /81) ‖ position one-hot ‖ global digit frequencies of the clues (9, scaled /81); linear;
  4. **permuted representation (primary H1 control):**
     - representations are permuted across puzzles within clue-count strata (all puzzles have 30 clues, so this is one stratum), separately for PROBE-TRAIN and PROBE-VAL with independent seeds;
     - the whole 81-cell grid moves together;
     - the probe is tuned on its own permuted PROBE-VAL;
     - at evaluation the permuted probe is applied to the **unpermuted** PROBE-VAL pairs, as on TEST;
  5. random features: standard-normal features of dimension 256 ‖ position, fixed per (puzzle, cell), with seed 0;
  6. label permutation: the 9-bit label vectors are permuted across all empty-cell examples of PROBE-TRAIN (seed 0); it is evaluated on true PROBE-VAL labels;
  7. teacher representation at levels 2, 6 and 12 (linear).
- **Marginal baseline:** per-position mean candidate bits on PROBE-TRAIN. Its Brier is computed on PROBE-VAL with the same aggregation.
- **H1 quantity on PROBE-VAL (planning only):** per puzzle, B_permuted − B_generated at level 6, linear probe, each probe at its own selected configuration, averaged over the 3 seeds.
- **Unit–digit target (D58, D62):** label = digit d already placed in unit u on the initial board ([n, 27, 9]; units from `UNITS`); readout = mean of the unit's 9 cell states ‖ unit one-hot (27), a linear probe shared across units with nine sigmoid outputs, same grid and seeds; metrics: exact match (all 9 digits correct at threshold 0.5), ROC-AUC (pooled over units × digits) and Brier; the raw-input version (mean of the unit's 9 raw own-cell one-hots ‖ unit one-hot) is reported next to it.
- **Equivariance (D59):**
  - 200 PROBE-VAL puzzles (the first 200 ids), each with 4 elements of the full group drawn by `random_symmetry(np.random.default_rng(0))` in a fixed order;
  - each transformed puzzle is re-run through the model;
  - the metric is the mean absolute difference between back-transformed and original predictions of the selected level-6 linear probe, over empty cells × 9 digits;
  - acceptable deviation = the 95th percentile of the puzzle-level mean absolute differences between the predictions of the 3 seed probes, taken pairwise on the untransformed puzzles;
  - digit-only and geometric-only subsets (2 extra elements each, from `random_symmetry(rng, kind)`) are reported separately.
- **H1 sample size (D60):**
  - shift the puzzle-level differences so their mean is 0.01: y = x − mean(x) + 0.01, clipped to [−1, 1];
  - target 90% power, with the 98.33% interval excluding 0, using `e2p2.interval`;
  - n = 100…3000 in steps of 100; 500 reps; 1,000 bootstrap resamples inside the simulation; seed 0;
  - report a shortfall if mean(x) < 0.01;
  - final TEST size = max(H1, 600), rounded up to 100.
- **Disk and memory:** each level is stored as a separate `float32` `.npy` file of shape [n, 81, 256], about 207 MB for 2,500 puzzles. Load one level at a time.
- Every written artifact states that it is non-confirmatory planning output.

## Review Focus

1. A transformation that maps the grid but not the digit channels, or that back-transforms the predictions with the forward rather than the inverse map. Expect `apply_symmetry` followed by the inverse to be the identity on grids, and on (81, 9) prediction arrays. Pinned by `test_inverse_roundtrip_grid_and_predictions` (Task 1).
2. Canonical form not invariant, or two inequivalent grids colliding. Pinned by `test_canonical_invariant_under_random_symmetries` and `test_canonical_distinguishes_random_grids` (Task 1).
3. A permuted-control leak, where train and val are permuted with the same seed, or the probe is evaluated on permuted val pairs. Pinned by `test_permuted_control_independent_and_eval_unpermuted` (Task 4).
4. Given cells entering the Brier or the training examples. Pinned by `test_brier_ignores_given_cells` (Task 3).
5. A selected configuration chosen on a single seed or on the training loss. Pinned by `test_select_uses_mean_val_brier_over_seeds` (Task 3).

**Interfaces:**
- Produces:
  - `Symmetry` (frozen dataclass): `transpose: bool`, `row_perm: tuple[int, ...]` (9, a valid band/row-within-band permutation), `col_perm: tuple[int, ...]` (9, stack/column-within-stack), `digit_perm: tuple[int, ...]` (10, with digit_perm[0] = 0).
  - `random_symmetry(rng, kind: str = "all") -> Symmetry`, with kind ∈ {"all", "digit", "geometric"}.
  - `apply_symmetry(grid: np.ndarray[81], s: Symmetry) -> np.ndarray[81]`: transpose first (if set), then permute rows and columns, then relabel digits.
  - `inverse(s: Symmetry) -> Symmetry`.
  - `transform_predictions(pred: np.ndarray[81, 9], s: Symmetry) -> np.ndarray[81, 9]`: moves cell rows and digit columns exactly as `apply_symmetry` moves cells and digits.
  - `canonical_form(solution: np.ndarray[81]) -> bytes`: the lexicographically minimal 81-byte string over the whole group. It must be exact. The average cost must be ≤ 0.5 s per grid on this CPU; prune the search (e.g. fix the first row's relabeling and minimise row by row). Mark the algorithm with a short comment that names its source idea.
  - `screen_canonical(subsets: dict[str, list[GeneratedPuzzle]], released_solutions: np.ndarray) -> dict` with keys `n_entries`, `classes` (lists of ids that share a canonical form, only classes of size ≥ 2) and `exact_duplicates`.

  - `select(results: dict[(wd, lr), list[float]]) -> tuple[float, float]`: the configuration with the lowest mean val Brier over seeds; ties go to the earliest entry in GRID order.
  - `fit_selected(features_tr, lab_tr, features_va, lab_va, kind, train_va=None) -> dict`:

    - `train_va` optionally gives a separate (features, labels) pair for tuning; the permuted control uses it.
