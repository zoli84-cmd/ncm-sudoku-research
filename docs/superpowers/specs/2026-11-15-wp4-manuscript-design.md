# WP4 design: integrated analysis, figures and arXiv preprint

Date: 2026-11-15. Status: draft for user approval. Decisions: D03 (arXiv preprint plus a workshop), D04 (repository public at publication), D83 (WP2 TEST complete), D84 (E4 dropped).

## Intent

Write up the preregistered NCM-Sudoku study (E1–E3, plan `research_plan_v3.7.md`, OSF https://osf.io/m28fx) as one complete arXiv preprint. There is no target workshop or deadline; a workshop-length version is cut from the preprint later, only when a concrete call appears. Plan §12.3 fixes the WP4 output: per-claim evidence, limitations and reproducible figures.

The why: the confirmatory results exist (`experiments/wp2/test/report.md`) and are only useful once they are reported in a form other researchers can read, check and reproduce, with the claim boundaries of plan §13 intact.

## Goals

- One arXiv-ready LaTeX manuscript in English (about 9 pages of main text plus appendices) reporting E1, E2 (H2, H3) and E3 (H1) with every pre-specified secondary and exploratory result.
- Every number in the manuscript comes from committed result files through generated LaTeX macros or generated tables; no result number is typed by hand.
- Figures and tables are produced by one script from committed files only and are reproducible from a clean checkout.
- The text keeps the plan §13 readings: each confirmatory result is stated with its justified claim and its "does not follow" boundary; results are conditional on the checkpoint and the intervention policy.
- Full disclosure: preregistration link and tag (`prereg-v3.7`), code tag (`wp2-code`), every post-lock decision that touches the analysis (D78 §7.4 reading, D79 naked-single F1 reading, D81–D82 post-freeze fixes before any TEST run, D84 E4 dropped on TEST results), and the non-confirmatory status of every pilot and preparation result.

## Non-goals

- No new confirmatory analysis, no model run, no re-evaluation of TEST; `experiments/wp2/test/` is read-only.
- No E4 or E5 work.
- No workshop version now.
- No submission to arXiv and no change of repository visibility without separate user approval.

## Anti-goals (failure even if it builds)

- A claim stronger than its §13 row (for example "the model computes candidates", "the model repairs logical errors").
- A hand-typed or stale number that differs from the result files.
- An exploratory or pilot result presented as confirmatory, or a descriptive table presented with inference it does not have (the E2 dose tables and the equivariance table carry no statistics).
- Silent omission of a pre-specified result because it is uninteresting or negative (for example the non-computable frozen-range AUC or the failed level-12 equivariance).

## Constraints

- Project rules (root `AGENTS.md`): files in English; plan §13 hedging, no compressed prose; never invent numbers; secrets only from the environment; never modify `third_party/ncm`.
- Inputs are committed files under `experiments/` (`wp2/test`, `wp2/dry`, `g0`, `wp1`, `e2p2`, `e3prep`, `lock`, `provenance`), `DECISIONS.md`, the plan and `literature/`. Raw `runs/` outputs are not inputs (git-ignored, not reproducible from a checkout).
- Toolchain: local Tectonic (single binary, user install, downloads LaTeX packages on first build; the Px proxy may need configuring, the user downloads it manually if the automated download fails; fallback MiKTeX user install). Python side uses the existing uv environment; matplotlib is added as a dependency (it is not in `pyproject.toml` yet).
- The `wp2-code` tag and everything it froze stay unchanged; WP4 code is new code on branch `wp4`.

## Approaches

| | Approach | Trade-off | Decision |
|---|---|---|---|
| A | LaTeX manuscript in the repository; one script generates figures, tables and number macros from committed results; local build | arXiv-native, every number traceable, buildable and checkable here; needs a LaTeX toolchain | **chosen by the user** |
| B | Markdown manuscript, pandoc to PDF | easier to write; arXiv wants LaTeX source, weaker tables and references, conversion at the end | rejected |
| C | Notebook-based analysis, manuscript separate | convenient exploration, but invites exploratory analysis around confirmatory results and blurs what was pre-specified | rejected |

Build location: local Tectonic chosen over Overleaf (user approval): the build can be verified here, generated files flow directly into the manuscript, unpublished results stay off external services (D04).

## Design

### Layout

- `paper/main.tex` plus one file per section under `paper/sections/`, `paper/refs.bib`; plain `article` class with `natbib`, `booktabs`, `graphicx`, `hyperref` (no venue style until a venue is chosen).
- `paper/generated/` (committed, regenerated by the script): `numbers.tex` (one `\newcommand` per reported number), `tables/*.tex`, `figures/*.pdf`.
- `scripts/wp4_figures.py`: reads the committed inputs, writes `paper/generated/`; deterministic, no network, no model, no statistics beyond reading and formatting stored values (any arithmetic it does, such as converting a proportion to percentage points, is formatting).
- `paper/AGENTS.md`: local contract (number-source rule, build command, claim-boundary rule); root index updated.

### Number rule and its check

- The manuscript writes results only through macros from `numbers.tex` or generated tables.
- A test scans `paper/sections/*.tex` for decimal numbers and percentages outside an explicit allowlist (section numbers, plan thresholds such as ±0.01 and ±3 pp, sample sizes defined in the plan) and fails on any other numeric literal.
- A test checks that every macro used in the sections is defined in `numbers.tex`, and the build fails on an undefined macro.

### Figures (proposal; styling left to the builder)

1. Design schematic: NCM levels and the four E2 branches (A baseline, B sham, C decode only, D continued generation); drawn in TikZ or as a static figure, no data.
2. E2 dose curves: solve share of C and D against dose for levels 2, 6 and 11 under both policies, with the level-1 enumeration as a separate marker; descriptive, labelled as such.
3. Primary and secondary contrasts: forest plot of H2, H3, θ₂′ and the policy and correct-baseline variants, with 98.33% and 95% intervals and the practical thresholds (5 pp, 3 pp, ±3 pp).
4. Propagation: mean later-level D code changes (level × configuration heat map) and the per-level state distances for the primary configurations.
5. E3 readability: Brier by level (2, 6, 12) for generated, permuted, teacher and raw-input probes; θ₁ per level with the ±0.01 band; H1 interval.
6. E3 supporting: training-size curve (whole-layer primary, per-cell secondary) and depth breakdown.

### Tables

1. Data subsets, sizes and generator provenance (gate, CAL, PROBE-TRAIN, PROBE-VAL, TEST; released set for G0).
2. Primary results: estimate, intervals, verdict and the §13 justified claim and "does not follow" row for H1, H2, H3.
3. E3 control matrix (generated, permuted, random features, label permutation, teacher, raw input, peer counts, surface, rule, marginal).
4. E1 summary; full E2 dose tables, equivariance and the frozen-range AUC outcome in the appendix.
5. Appendix: deviations and readings (D78, D79, D81, D82, D84) and compute.

### Manuscript outline

1. Abstract.
2. Introduction: question, preregistration, summary of the three confirmatory results with their boundaries.
3. Background and related work (NCM, Sudoku transformers, probing and patching caveats); based on `literature/related_work_novelty_check.md`; the related-work search is repeated before submission (open item in `ROADMAP.md`).
4. Setup: checkpoint and G0 reproduction, own generator and distribution gate, splits, labels (candidate mask, waves, depth), statistical plan (family intervals, TOST, rare-event bound), code freeze and dry run.
5. E1: tokenizer versus generator.
6. E2: level sensitivity (H2), compensation (H3), levels 2 versus 11, dose curves, propagation.
7. E3: level-6 readability (H1), controls, level 12, depth, training size, exploratory equivariance.
8. Discussion and limitations: §13 risks and their controls, one checkpoint and one task, E4 not run and why (D84), what the results do not show.
9. Appendices as in the table list; reproducibility statement (tags, OSF, commands).

### Process

- Phase 1 (one implementation plan): Tectonic setup, `scripts/wp4_figures.py` with tests (TDD), the number checks, the LaTeX skeleton with section stubs and generated figures and tables; done when the skeleton builds and every check passes. Tectonic setup is the plan's first step; if the automated download fails the plan stops until the user has installed it.
- Verification split (designer's call): the number-rule and macro checks are pytest tests and need no LaTeX; the PDF build is a separate command (`tectonic paper/main.tex`) run as the build check, and its pytest wrapper is skipped when no `tectonic` binary is on the path.
- Phase 2 (drafting, outside the implementation plan): sections in order Setup, E1, E2, E3, Discussion, Introduction, Abstract last; the user reviews each section draft before the next one starts; the central message (below) is fixed before the Introduction is written.
- Placeholders (designer's call): author, affiliation and licence appear as `\placeholder{...}` macros; the build check fails in an `--arxiv` mode while any placeholder remains.
- External Copilot review of the full manuscript with the `copilot-review` skill; tier decided at that point (a public artifact suggests high).
- Before submission: repeat the related-work search; separate user approval for arXiv submission and for making the repository public.

## Central message

User decision (2026-11-15): an integrated picture. The question is where the Sudoku logic sits in a coarse-to-fine generator. Errors are most costly at the coarsest level and later generation partly compensates (H2, H3); candidate information is readable from the intermediate level-6 state with the examined probe family only below the practical threshold, while it is trivially readable from the input (H1, raw-input controls); at level 12 the representation is consistent with solution content but not equivariant. The study is presented as preregistered and confirmatory, null-type results included; the title, the Introduction and the figure order follow this framing.
