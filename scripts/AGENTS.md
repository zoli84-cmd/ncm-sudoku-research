# scripts

DOX rules and project contracts are inherited from the project root [AGENTS.md](../AGENTS.md).

## Purpose

Command-line entry points that fetch data, generate subsets, run experiments, and write committed results under `experiments/` and raw outputs under `runs/`.

## Ownership

- Owns every script in this folder; script tests live in `tests/` (`test_*_script*.py`, `test_lock_*.py`, `test_e3_*.py`)

## Local Contracts

- Most result writers are rerun-guarded and refuse to overwrite unless `--force` (or `--resume`) is given; check the per-script contract below before forcing a rerun
- `wp1_gate.py` is single-look: `experiments/wp1/gate.json` must never be regenerated
- WP2 runners take `--role test|dry` and `--force | --resume` through `ncm_sudoku.wp2.parse_args` and are guarded by `wp2.guard_start`
- TEST-role runs are single-look: no `--force`; `--resume` only for incomplete runs; any other rerun is a logged deviation; only valid run records count

## Work Guidance

Completed (D83); kept unchanged because D81-D83 cite its step numbers and it records the single-look and dry-snapshot rules.

WP2 freeze/dry/TEST runbook (run every command from the project root as `uv run --locked python scripts/<script> ...`; without `--locked`, `uv run` may re-lock or re-sync, which dirties `uv.lock` or changes the environment, and a later `--resume` is then refused):

1. Whole-branch review.
2. `git tag wp2-code` on the reviewed commit.
3. Dry run, in this order, each one exiting 0 before the next starts:
   - `wp2_e3_extract.py --role dry`
   - `wp2_e3.py --role dry`
   - `wp2_equiv.py --role dry`
   - `wp2_e2.py --role dry`
   - `wp2_e1.py --role dry`
   - `wp2_evaluate.py --role dry`; a nonzero exit means stop as in step 4, without running the dry check
   - `wp2_dry_check.py`; its `dry_evaluate` part requires the dry `results.json` and `report.md` at the tag commit, clean, and computed from the current dry outputs
4. If `technical_success` is false: stop and investigate. Any fix needs re-review and re-tagging before any TEST run, logged in `DECISIONS.md`. The TEST guard refuses to start without a passing `check.json` at the tag commit.
5. Do not commit anything, and do not edit `src/`, `scripts/`, `pyproject.toml`, `uv.lock` or `third_party/ncm`, between the tag and the end of step 7; any such change makes the affected records invalid. From step 3 until the end of step 7, also leave unchanged (the dry outputs from the moment their runner writes them in step 3) `runs/wp2/dry/`, `experiments/wp2/dry/`, the pre-lock references the dry check reads (`runs/e2p2/pilot2.json`, `runs/lock/level1_full_batch.json`, `experiments/e3prep/probes.json`, `experiments/e3prep/wholelayer.json`, `experiments/lock/equivariance_l12.json`) and `runs/e3prep/`, and rerun no dry runner (nor the dry evaluation or dry check): a dry rerun deletes `check.json`, and every TEST start, `--resume` included, re-hashes the approved snapshot.
6. TEST run, sequentially in the background (D76(5)):
   - `wp2_e3_extract.py --role test`
   - `wp2_e3.py --role test`
   - `wp2_equiv.py --role test`
   - `wp2_e2.py --role test`
   - `wp2_e1.py --role test`

   Between runs, check only the exit code and the `complete`, `valid` and `status` fields of the run record. An interrupted run continues with `--resume`. Exit code 3 (E2 `identity-failure`) or any `valid: false`: stop the sequence, keep every artifact, and write a deviation entry in `DECISIONS.md` before anything else, but leave it uncommitted until step 8: a commit moves HEAD off the tag, and the TEST evaluation then refuses.
7. `wp2_evaluate.py --role test`; results are read only now. It renders `report.md` before writing either output, so a failure leaves no `results.json` behind and the single look stays available.
8. Commit `experiments/wp2/`, then add the `DECISIONS.md` entry (and commit any deviation entry written in step 6).
