# src/ncm_sudoku

DOX rules and project contracts are inherited from the project root [AGENTS.md](../../AGENTS.md).

## Purpose

Own Python package `ncm_sudoku`: Sudoku core, model instrumentation, and the experiment logic used by `scripts/`.

## Ownership

- Owns every module in this folder; one test module per package module lives in `tests/`

## Local Contracts

- `grid.PEER_ORDER` is a frozen literal (81 × 20); never reorder it, `tests/test_peer_order.py` pins the `PEER_IDX` SHA-256
- Load checkpoints only through `model.load_model` (weights_only=True)
- WP4 modules (`wp4numbers`, `wp4tables`, `wp4figures`, `texlint`) only read committed result files and format them; they compute no statistic, load no model and import no `torch`
- `wp2.py` is the shared WP2 infrastructure: every WP2 runner starts with `wp2.guard_start` and ends with `wp2.finish_run`, prints only through `wp2.status_line` (technical keys only), writes only through the `wp2.atomic_*` helpers (directory publishes through `wp2.replace_with_retry`; never a bare `os.replace`), and gets its puzzles from `wp2.load_role`
- `guard_start` writes the (incomplete) run record before a fresh start's `clear_outputs` call, so a refused fresh TEST start over unrecorded leftover outputs still leaves an incomplete, markerless record behind; every runner must therefore mark a fresh start with `wp2.mark_outputs_started` right after `clear_outputs` succeeds (before writing any output) and gate `--resume` on that marker by reassigning `rec = wp2.prepare_resume_outputs(...)` (it marks and returns the record itself when there is no marker and no target yet exists, e.g. a crash between `clear_outputs` and `mark_outputs_started`, so a later `--resume` is never wedged), never touching output targets directly on `--resume` without it

## Verification

- From the project root: `uv run pytest -q`
