\section{Setup}
\label{sec:setup}

\subsection{Model and reproduction}
\label{sec:setup-model}

We study the released Sudoku-hard checkpoint of Next-Concept Modeling (NCM) \citep{kumbong2026ncm}, run with the upstream code at a pinned commit and never retrained or modified. NCM represents a completed grid as a hierarchy of \R{model.levels} levels of discrete codes, each drawn from a codebook of \R{model.codes} entries. The number of codes grows from a single code at level~1 to \R{model.tokens} at level~\R{model.levels}, the length of the output token sequence, and each code is embedded in \R{model.dim} dimensions. The generator produces the levels in order, coarse to fine, conditioned on the puzzle; the decoder maps the cumulative state of all levels to the solution grid. The released configuration decodes greedily, so generation is deterministic.

All runs use single-precision (FP32) floating point, eager execution and deterministic algorithms on a CPU. The published evaluation also runs in FP32 and eager mode; the only planned difference is the device, CPU instead of GPU kernels. Before any analysis we reproduced the published result on the \R{g0.n} released hard puzzles (G0): the official exact-match metric gave \R{g0.official}\% against the published \R{g0.published}\%, inside the pre-specified tolerance of $\pm$\R{g0.tol} percentage points. The intervention path passed identity checks that are required to hold exactly: with interventions disabled the output is unchanged, writing back the model's own code at any level changes nothing, and saved cumulative states are not overwritten by later levels. Our own validator, which checks rules, clue preservation and format independently of the reference solution, gave a solve share of \R{g0.own}\% on the same puzzles.

\subsection{Puzzles and data splits}
\label{sec:setup-data}

Except for the reproduction, every puzzle comes from our own generator, written from scratch: a complete grid is drawn by randomized backtracking, and clues are removed one at a time in random order as long as the solution stays unique, until exactly \R{data.clues} clues remain, the clue count of the released hard set. The generator was frozen before any analysis subset was drawn, and a single terminal distribution check compared one fresh batch of \R{gate.n} puzzles with the released set. Without the model, the distribution of solver depth differed by a total variation distance of \R{gate.tvd} (threshold \R{gate.tvd.thr}). With the model, the solve share on the fresh batch was \R{gate.fresh}\% against \R{gate.bench}\% on the released set; the \R{gate.ci.level}\% interval of the difference, [\R{gate.ci.lo}, \R{gate.ci.hi}] percentage points, lay inside the pre-specified equivalence range of $\pm$\R{gate.margin} points. The check does not show that the fresh puzzles follow the unreleased training distribution of the checkpoint; it shows that they are not harder or easier for the model than the released evaluation set by more than the stated range.

Separate seed ranges produce separate subsets: a calibration set for pilots and sample-size planning, \R{probe.train} puzzles for training probes (PROBE-TRAIN), \R{probe.val} for model selection (PROBE-VAL), and \R{n.test} confirmatory TEST puzzles. Every subset was screened for exact duplicates and for symmetry-equivalent puzzles across subsets. TEST was generated during the preparation of the preregistration, without running the model on it, and its puzzle identities and hashes were fixed in the registration; it was used only for the runs reported here. Two further seed ranges, reserved for the conditional causal study (Section~\ref{sec:discussion}), were never used.

\subsection{Logical labels}
\label{sec:setup-labels}

For each originally empty cell and each digit, the candidate label is one if the digit does not appear among the filled cells of the same row, column or box. This nine-bit candidate mask is a shallow rule: it is a deterministic threshold of the peer digit counts, so a model of the raw input can reach it exactly, and we report such input-based controls next to every readout. A naked single is a cell with exactly one candidate.

The inference depth of a cell comes from a deterministic solver that applies only naked- and hidden-single rules in synchronous waves, without guessing and without reading the solution. Depth $k$ means the cell is first filled in wave $k$; cells the rules never fill are marked stuck. The depth strata are 1, 2, 3, at least 4, and stuck. The model always receives the original puzzle; solver states are never fed back, and model levels are not identified with solver waves.

\subsection{Preregistration and statistical plan}
\label{sec:setup-stats}

The protocol, hypotheses, thresholds, sample sizes and interpretation rules were registered before any model run on TEST and before any TEST outcome existed (OSF, \url{https://osf.io/m28fx}, embargoed until publication; repository tag \texttt{prereg-v3.7}). The primary family has three contrasts, H1 to H3, each tested with a two-sided Bonferroni interval of \R{level.family}\% nominal coverage, targeting a family-wise error rate of \R{stat.alpha}\%; bootstrap coverage is approximate. Intervals are percentile cluster bootstraps over puzzles with \R{stat.nboot} resamples; when fewer than twenty puzzles have a nonzero difference in a contrast, a conservative rare-event bound replaces the bootstrap. The practical thresholds were fixed in advance: \R{plan.h2practical} percentage points for H2, \R{plan.h3practical} for H3, an equivalence range of $\pm$\R{plan.theta2pmargin} points for the secondary comparison of levels 2 and 11, and $\pm$\R{plan.h1margin} in Brier loss for H1, whose equivalence reading uses a two one-sided test at the family level (\R{level.tost}\% interval). Each confirmatory result is reported with the claim it supports and the claims that do not follow from it, as fixed in the registered interpretation table.

\paragraph{Changes before the lock.} Three choices concerning the primary hypotheses were changed during preparation, on calibration and probe-selection data only, before the registration and before TEST was used: the primary H2 contrast moved from level~2 to level~1, after a pilot in which levels 2 to 11 barely changed the solve share; H3 moved to level~1 as well, because at level~2 under the frequency policy decoding a replaced code never changed the solve outcome in the pilot, so the compensation contrast there could only measure regeneration; and the primary H1 probe changed from a per-cell probe to the cell-relative whole-layer probe of Section~\ref{sec:e3-design}, with H1 recast as a two-sided contrast with an equivalence range, after the per-cell estimate on PROBE-VAL came out close to zero. The registration stated the expected H1 outcome as readability above zero but inside the equivalence range. All three changes were logged with their reasons. The H1 changes make an absence claim harder rather than easier to reach; the H2 and H3 changes, in contrast, moved the tests to the level where the pilot had shown an effect, so their confirmatory value rests on the fresh TEST puzzles.

\paragraph{Execution.} All analysis code was frozen under a git tag before any model ran on TEST. A dry run of the frozen code on non-TEST data had to reproduce earlier pilot outputs exactly before TEST could start, and a pre-written script evaluated TEST once. Decisions taken after the registration are listed in Appendix~\ref{sec:appendix-deviations}.
